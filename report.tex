\begin{abstract}
The exploration of transient astronomical events via resource-constrained CubeSats necessitates highly efficient onboard data triage to overcome severe downlink limitations. Traditional systems employ binary "keep-or-delete" algorithms, which risk discarding critical pre-event early-rising data due to low initial signal-to-noise ratios. In this report, we detail the implementation of EventVault-R (Phase A), a software reference model of a progressive, uncertainty-bounded science-data escrow architecture. EventVault-R utilizes a 3-level Discrete Wavelet Transform (DWT) codec coupled with a circular escrow buffer. This design enables the proactive storage of residual high-frequency data and permits retroactive promotion upon positive transient confirmation. Experimental results confirm a 100\% recovery rate of pre-trigger observations with zero uncontrolled data loss, satisfying strict photometric ($\Delta F \leq 0.5\%$) and astrometric ($\Delta x \leq 0.1$ px) error bounds. 
\end{abstract}

\section{Introduction}
Modern CubeSat constellations offer unprecedented continuous sky coverage but are severely limited by low-bandwidth telemetry downlinks (often $<10$ kbps). To maximize scientific yield, onboard processing algorithms must identify and prioritize valuable astronomical transients (e.g., supernovae, gamma-ray burst optical afterglows, and fast radio bursts) before downlink. However, naive triage systems discard pre-event observations when transients are too faint to confidently detect, losing vital information about the early physical mechanisms of the events.

EventVault-R addresses this by splitting images into coarse base layers (retained long-term) and fine detail layers (held temporarily in an escrow buffer). If a transient is confidently detected at a later time $T_{trig}$, the system retroactively "promotes" the pre-trigger detail layers for the preceding $\Delta T_{pre}$ window.

This paper outlines the completion of the Phase A software reference model, detailing the modules constructed, the integration tests performed, experimental verification of the core novelty, and the roadmap for upcoming firmware/hardware implementations.

\section{Architecture and Completed Implementation}

The Phase A implementation provides a Python-based, deterministic reference model. We have fully implemented all 10 planned sub-modules within the EventVault-R architecture.

\subsection{Acquisition and Calibration}
A synthetic data generator was built to inject realistic Poisson-noise astronomical sources and transients into 2D detector frames. Standard dark-current subtraction and flat-fielding calibration modules were implemented to ensure detector artifacts do not bias uncertainty estimations.

\subsection{Progressive Wavelet Codec}
A 3-level 2D Discrete Wavelet Transform (DWT) engine is implemented, generating a base layer ($L_0$) and three detail layers ($H_1, H_2, H_3$). Progressive reconstruction was verified across multiple wavelet bases (Haar, db4, bior4.4), guaranteeing prefix-decode validity at any truncation depth. 

\subsection{Science Guardrail}
The Science Guardrail module evaluates whether dropping a specific detail layer violates strict scientific utility bounds. It extracts sources and computes the photometric flux error ($\Delta F$) and astrometric centroid error ($\Delta x$). Deletion of detail layers is only permitted if $\Delta F \leq \epsilon_F$ (default 0.5\%) and $\Delta x \leq \epsilon_x$ (default 0.1 pixels).

\subsection{Circular Escrow Buffer and Promotion}
The core memory management system is a finite circular buffer with strict lock/unlock and per-layer purge semantics. It guarantees zero uncontrolled data loss by refusing to blindly overwrite locked entries. The associated \textit{Promotion Controller} allows the system to retroactively sweep through the $T_{trig} - \Delta T_{pre}$ window and mark pre-event residual layers as protected for priority downlink.

\subsection{Uncertainty Estimation and Resource Control}
Uncertainty estimation was implemented using softmax entropy and Mahalanobis distance metrics. Crucially, uncertainty \textit{increases} the retention priority of an observation to protect novel out-of-distribution (OOD) events. Additionally, a deterministic rule-based Resource Controller links spacecraft state (memory and battery) to operating parameters, shrinking the escrow horizon during high memory pressure.

\subsection{End-to-End Pipeline}
The central control loop successfully ties together calibration, DWT decomposition, guardrail evaluation, escrow pushing, uncertainty scoring, and telemetry queueing into a continuous deterministic sequence (Algorithm 1).

\section{Experimental Results}

The implementation was validated against two primary experiments: the Rate-Distortion analysis and the Saved Discovery simulation.

\subsection{Rate-Distortion Analysis}
The codec was evaluated to verify compliance with the target bounds ($\epsilon_F = 0.5\%$, $\epsilon_x = 0.1$ px) across different wavelets. The Haar wavelet provided maximum compression (CR = 64.0 for base-only) but violated the guardrail limits. The \texttt{bior4.4} and \texttt{db4} wavelets successfully met the stringent scientific fidelity limits at depth 3 (full reconstruction) and depth 2 (high compression), proving that significant bandwidth savings can be achieved without corrupting science data.

\subsection{Saved Discovery Experiment}
The hallmark EventVault-R test involved a 60-frame sequence (cadence 30s) where a transient begins rising at $T_{10}$ but is not confidently detected until $T_{25}$. 

A naive triage baseline algorithm successfully identified the transient at $T_{25}$ but failed to recover the pre-trigger frames between $T_{10}$ and $T_{24}$ because their signal-to-noise ratio fell below the immediate-triage threshold.

In contrast, EventVault-R temporarily stored the high-frequency residuals in the escrow buffer. Upon detection at $T_{25}$, the Promotion Controller swept the buffer and successfully recovered 100\% of the pre-trigger observations. During the simulation, the system registered 0 uncontrolled buffer overflows, verifying the robustness of the retention guardrails.

\section{Remaining Work}

With Phase A (Software Reference Model) successfully completed and tested, the project must now transition to the embedded and hardware-accelerated phases.

\subsection{Phase B: Embedded C/C++ Port}
The Python reference model must be translated to memory-safe C/C++ suitable for real-time operating systems (RTOS) running on CubeSat flight computers (e.g., ARM Cortex-M or RISC-V). This requires fixed-point implementations of the DWT codec to avoid floating-point overhead, and static memory allocation for the escrow buffer to prevent heap fragmentation.

\subsection{Phase C: Hardware Acceleration (FPGA)}
To handle megapixel images at high frame rates, the progressive DWT and initial source extraction (Guardrail processing) should be offloaded to an FPGA (e.g., Xilinx Zynq). The remaining task includes writing Verilog/VHDL IP cores for the wavelet transforms and validating their outputs against the Python reference model.

\subsection{Flight Qualification Testing}
The integrated software/hardware stack must undergo strict profiling for power consumption ($<2$ W target), execution latency, and radiation-induced Single Event Upset (SEU) resilience.

\section{Conclusion}

The software reference model of EventVault-R is complete. Testing confirms the viability of a progressive, uncertainty-bounded escrow architecture for transient astronomy. By deferring irreversible data destruction, EventVault-R successfully recovers early-rising photometric data that traditional systems would discard, offering a massive leap in capability for resource-constrained CubeSat operations.
